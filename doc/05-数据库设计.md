# 05 数据库设计

## 5.1 总览

- 数据库：SQLite 单文件 `<data>/mydata.db`。
- 建表：应用启动时由 Rust `platform/database_init.rs` 的 `init_database()` 执行全部 `CREATE TABLE IF NOT EXISTS`。
- 访问：Rust 通过 `rusqlite` 直接打开，无 ORM、无连接池、无迁移版本表。
- 时间：`Read_Books` / `Read_Annotation` 的时间列为 `DATETIME` 文本（UTC，`YYYY-MM-DD HH:MM:SS.mmm`，可按字符串排序）；`Note_Content`、`sync_operations`、`app_config` 仍为 Unix 毫秒（`INTEGER`）。
- 软删除：书籍通过 `Read_Books.Delete_Time` 标记，标注通过 `Read_Annotation.Delete_Time` 标记，笔记通过 `Note_Content.Delete_Time` 标记；查询统一过滤未删除记录。
- 笔记、书籍、标注都使用各自独立的自增编号主键表（`Note_Content` / `Read_Books` / `Read_Annotation`），编号在各设备独立分配，因此暂不参与跨设备同步。

## 5.2 实体关系

```
┌──────────────────┐         ┌────────────────────────┐
│  Read_Books    │  逻辑   │  Read_Annotation    │
│  Book_ID (PK)    │◄───────┤  Annotation_ID (PK)    │
│  Book_Hash       │ 1:N     │  Book_ID ──────────────┘
└──────────────────┘         └────────────────────────┘

┌──────────────────┐         ┌────────────────┐
│   Note_Content   │  冗余   │  Note_Folders  │
│ Note_ID (PK)     │───────► │ Folder_ID (PK) │◄──┐ 自关联
│ Is_Folder        │  路径   │ Folder_Parent_ID ───┘
│ Folder1 / 2 / 3  │         └────────────────┘
└──────────────────┘
```

说明：

- SQLite 默认未显式开启 `PRAGMA foreign_keys = ON`，因此表间关系是**逻辑约束**，完整性由业务代码维护。
- `Read_Annotation.Book_ID` 指向 `Read_Books.Book_ID`，删除书籍时由 `delete_book` 级联软删除其标注。
- 文件夹删除是物理删除，笔记通过重建 `Is_Folder` + `Folder1~3` 重新指向父文件夹或「未命名」。
- `Note_Content` 与 `Note_Folders` 之间没有外键，路径以冗余列保存，文件夹层级变化时由 `refresh_note_paths()` 重建。

## 5.3 表结构

### 5.3.1 `Read_Books` — 书籍表

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `Book_ID` | VARCHAR(10) | PK, NOT NULL | 十位补零编号，从 `0000000001` 自增，最大 `9999999999` |
| `Book_Title` | TEXT | NOT NULL DEFAULT '' | 书名（导入时取文件名去掉扩展名） |
| `Book_Author` | TEXT | NOT NULL DEFAULT '' | 作者，当前解析不到时为空字符串 |
| `Book_Hash` | CHAR(64) | NOT NULL DEFAULT '' | 源文件 SHA-256，用于导入去重；旧数据迁移时为空 |
| `File_Path` | TEXT | NOT NULL | 书籍文件绝对路径，通常位于 `<data>/books/` |
| `File_Format` | VARCHAR(8) | NOT NULL | `epub` / `pdf` / `mobi` / `txt` |
| `Total_Pages` | INTEGER | NOT NULL DEFAULT 0 | PDF 页数 / EPUB spine 数 / TXT 章节数（与阅读器解析结果一致） |
| `Current_Page` | INTEGER | NOT NULL DEFAULT 0 | PDF 页码（1 起）/ TXT 章节号（1 起）/ EPUB 未使用 |
| `Reading_Status` | VARCHAR(12) | NOT NULL DEFAULT 'unread' | `unread` / `reading` / `finished` |
| `Cover_Url` | TEXT | NULL | 封面 URL，当前未使用 |
| `Create_Time` | DATETIME | NOT NULL | 创建时间（UTC 文本） |
| `Update_Time` | DATETIME | NOT NULL | 更新时间（UTC 文本），列表排序依据 |
| `Delete_Time` | DATETIME | NULL | 软删除时间；NULL 表示未删除 |
| `Device_ID` | TEXT | NOT NULL DEFAULT '' | 最后写入设备的 ID |
| `Version` | INTEGER | NOT NULL DEFAULT 1 | 每次创建/更新/删除 +1，当前只记录不参与合并 |

索引：

```sql
CREATE INDEX idx_read_books_hash ON Read_Books (Book_Hash, Delete_Time);
CREATE INDEX idx_read_books_list ON Read_Books (Delete_Time, Update_Time);
```

编号规则：`next_book_id` 取 `MAX(CAST(Book_ID AS INTEGER)) + 1`，格式化为 `{:010}`；不回收已删除编号，超过 `9999999999` 返回错误。

### 5.3.2 `Note_Content` — 笔记表

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `Note_ID` | VARCHAR(10) | PK, NOT NULL | 十位补零编号，从 `0000000001` 自增，最大 `9999999999` |
| `Note_Title` | VARCHAR(20) | NOT NULL DEFAULT '' | 标题；Rust 侧校验最多 20 个字符 |
| `Note_Content` | TEXT | NOT NULL DEFAULT '' | 正文（Markdown 或纯文本） |
| `Tags` | TEXT | NOT NULL DEFAULT '[]' | JSON 字符串数组，如 `["学习","idea"]` |
| `Create_Time` | INTEGER | NOT NULL | 创建时间（Unix 毫秒） |
| `Update_Time` | INTEGER | NOT NULL | 更新时间（Unix 毫秒），列表排序依据 |
| `Delete_Time` | INTEGER | NULL | 软删除时间；NULL 表示未删除 |
| `Device_ID` | TEXT | NOT NULL DEFAULT '' | 最后写入设备的 ID |
| `Version` | INTEGER | NOT NULL DEFAULT 1 | 每次创建/更新/删除 +1，当前只记录不参与合并 |
| `Is_Folder` | CHAR(1) | NOT NULL, CHECK IN ('0','1','2','3') | 当前所在文件夹层级，对应 `Note_Folders.Folder_Level`；`0` 表示默认文件夹「未命名」 |
| `Folder1` | CHAR(4) | NULL | 一级（最上层）文件夹编号 |
| `Folder2` | CHAR(4) | NULL | 二级文件夹编号 |
| `Folder3` | CHAR(4) | NULL | 三级（当前）文件夹编号 |
| `Is_Pinned` | CHAR(1) | NOT NULL DEFAULT '0', CHECK IN ('0','1') | 置顶标记，`1` 置顶 |

路径冗余规则（`Is_Folder` 与 `Folder1~3` 必须同时维护）：

| Is_Folder | Folder1 | Folder2 | Folder3 |
|---|---|---|---|
| `0` | NULL | NULL | NULL |
| `1` | 当前文件夹 ID | NULL | NULL |
| `2` | 父文件夹 ID | 当前文件夹 ID | NULL |
| `3` | 祖父文件夹 ID | 父文件夹 ID | 当前文件夹 ID |

索引：

```sql
CREATE INDEX idx_note_content_folder
  ON Note_Content (Is_Folder, Folder1, Folder2, Folder3);
CREATE INDEX idx_note_content_list
  ON Note_Content (Delete_Time, Is_Pinned, Update_Time);
```

列表排序统一为 `Is_Pinned DESC, Update_Time DESC`。按文件夹筛选时只看「当前层级对应的列」，避免把后代文件夹中的笔记误算进来。

### 5.3.3 `Note_Folders` — 文件夹表

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `Folder_ID` | CHAR(4) | PK, NOT NULL | 四位补零编号，从 `0001` 自增，最大 `9999` |
| `Folder_Name` | VARCHAR(20) | NOT NULL | 名称，Rust 侧校验去空格后 1–20 字符 |
| `Folder_Level` | CHAR(1) | NOT NULL, CHECK IN ('0','1','2','3') | 0=默认「未命名」；1–3=用户文件夹层级 |
| `Folder_Parent_ID` | CHAR(4) | NULL | 父文件夹编号；NULL 表示根级 |
| `Folder_Parent_Name` | VARCHAR(20) | NULL | 冗余保存父文件夹名称，父级重命名时同步更新 |
| `Folder_Order` | CHAR(4) | NOT NULL | 同级排序号，按 `CAST(... AS INTEGER)` 排序 |
| `Folder_Flg1` | CHAR(10) | NULL | 预留标志位 |
| `Folder_Flg2` | CHAR(10) | NULL | 预留标志位 |
| `Folder_Flg3` | CHAR(10) | NULL | 预留标志位 |

索引：

```sql
CREATE UNIQUE INDEX idx_note_folders_unique
  ON Note_Folders (Folder_Name, Folder_Level, IFNULL(Folder_Parent_ID, ''));
CREATE INDEX idx_note_folders_parent_order
  ON Note_Folders (Folder_Parent_ID, Folder_Order);
```

唯一索引的键包含层级与父级，因此：

- 同一父级、同一层级下不能重名；
- 不同父级允许同名；
- 根级（`parent_id = NULL`）借助 `IFNULL` 参与唯一约束。

排序规则：

- 默认「未命名」：`Folder_Level = 0`、`Folder_Order = 0`，始终排在最前；
- 用户文件夹：同级 `Folder_Order` 从 1 开始，新建时取同级最大值 +1。

编号规则：

- `next_folder_id` 取 `MAX(CAST(Folder_ID AS INTEGER)) + 1`，格式化为 `{:04}`；
- 不回收已删除编号；超过 9999 返回错误「文件夹编号已用完（最多 9999 个）」。

层级规则：

- `Folder_Level` 由后端根据父级计算，不由前端传入；
- 根级为 1，最大 3；
- 默认文件夹层级为 0，且禁止在其下创建子文件夹；
- 删除文件夹导致子级上移时，其后代层级递归减 1；根级文件夹的子级上移后仍为层级 1（`new_level = 被删文件夹的 level`）。

### 5.3.4 `Read_Annotation` — 标注表

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `Annotation_ID` | VARCHAR(10) | PK, NOT NULL | 十位补零编号，从 `0000000001` 自增 |
| `Book_ID` | VARCHAR(10) | NOT NULL | 所属书籍 `Read_Books.Book_ID` |
| `Annotation_Text` | TEXT | NOT NULL | 选中文本 |
| `Annotation_Note` | TEXT | NOT NULL DEFAULT '' | 备注，当前创建时为空 |
| `Page` | INTEGER | NOT NULL DEFAULT 0 | PDF 页码 / TXT 章节号；EPUB 创建时传 0 |
| `Position` | TEXT | NOT NULL DEFAULT '' | 定位 JSON，见下表 |
| `Color` | VARCHAR(16) | NOT NULL DEFAULT '#FFEB3B' | 高亮颜色 |
| `Create_Time` | DATETIME | NOT NULL | 创建时间（UTC 文本） |
| `Update_Time` | DATETIME | NOT NULL | 更新时间（UTC 文本） |
| `Delete_Time` | DATETIME | NULL | 软删除时间；NULL 表示未删除 |
| `Device_ID` | TEXT | NOT NULL DEFAULT '' | 最后写入设备的 ID |
| `Version` | INTEGER | NOT NULL DEFAULT 1 | 每次创建/更新/删除 +1 |

`Position` 按格式存放不同 JSON：

| 格式 | 示例与含义 |
|---|---|
| EPUB | `{"cfi":"epubcfi(...)"}`，epubjs 的 CFI 定位 |
| PDF | `{"page":3,"rects":[{"x":0.12,"y":0.34,"w":0.2,"h":0.02}],"text":"..."}`，矩形归一化到页面尺寸（0~1） |
| TXT | `{"chapter":12,"start":340,"end":365,"text":"..."}`，章节序号 + 章节纯文本内字符偏移 |

索引：

```sql
CREATE INDEX idx_read_annotation_book ON Read_Annotation (Book_ID, Delete_Time, Page);
```

查询排序：`Page ASC, Create_Time ASC`。删除书籍时同事务把其未删除标注一并软删除。

### 5.3.5 `sync_operations` — 操作日志（只写不读）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | TEXT | PK | UUID v4 |
| `document_id` | TEXT | NOT NULL | 关联文档 |
| `operation` | TEXT | NOT NULL | `create` / `update` / `delete` |
| `field` | TEXT | NULL | 字段名，更新/删除时为空 |
| `value` | TEXT | NULL | 字段值 |
| `timestamp` | INTEGER | NOT NULL | 操作时间 |
| `device_id` | TEXT | NOT NULL | 操作设备 |
| `synced` | INTEGER | NOT NULL DEFAULT 0 | 是否已同步；当前始终为 0 |

现状：笔记的 create/update/delete、书籍的 create/update/delete、标注的 create 会写入（`document_id` 列存对应的 `Note_ID` / `Book_ID` / `Annotation_ID`）；标注删除与文件夹操作不写；同步流程完全未读取此表。

### 5.3.6 `app_config` — 键值配置

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `key` | TEXT | PK | 配置键 |
| `value` | TEXT | NOT NULL | 配置值（字符串） |
| `updated_at` | INTEGER | NOT NULL | 更新时间 |

写入使用 `INSERT ... ON CONFLICT(key) DO UPDATE`。

当前使用的键：

| 键 | 值 | 用途 |
|---|---|---|
| `sync.receive.enabled` | `'true'` / `'false'` | 同步开关，启动时恢复服务 |
| `device.name` | 文本 | 设备显示名称 |

## 5.4 启动迁移

启动顺序：`platform::database_init::init_database()` 建表 → `modules::notepad::init()` → `modules::reader::init()`。

`modules::notepad::init()` 先调用 `ensure_note_content_columns()` 补齐后加的列，再依次调用 `migrate_legacy_folders()` → `ensure_default_folder()` → `migrate_legacy_notes()`，最后在一个事务中执行 `refresh_note_paths()`。

### 迁移旧阅读器表

触发条件：`sqlite_master` 中存在名为 `documents` 的表（`books` / `annotations` 任一存在即一并迁移）。

规则：

1. `documents d INNER JOIN books b` 读取旧书籍，按 `created_at` 升序重新编号 `Book_ID`（`0000000001` 起，十位补零），`Book_Hash` 留空（旧数据无哈希，不参与去重）；其余字段映射到 `Read_Books` 的同义列，旧的毫秒时间戳转换为 `DATETIME` 文本；
2. 记录旧 `document_id -> 新 Book_ID` 映射，再迁移 `annotations`：按 `created_at` 重新编号 `Annotation_ID`，`book_id` 换成新编号；找不到所属书籍的标注跳过并写警告日志；
3. 全流程单事务；成功后按外键顺序依次 `DROP TABLE annotations`、`DROP TABLE books`、`DROP TABLE documents` 再提交；
4. 失败整体回滚并保留旧表，下次启动重试。

迁移日志：`[Reader] 阅读器表迁移完成: N 本书 / M 条标注 -> Read_Books / Read_Annotation`。

> 由于 `documents` 的建表语句已从 `database_init.rs` 移除，迁移完成后不会再被重新创建。

### 迁移旧 `folders` 表

触发条件：`sqlite_master` 中存在名为 `folders` 的表。

数据来源：`folders(id, name, parent_id, sort_order)`。

规则：

1. 旧「未分类」`uncategorized` 映射为 `0001 / 未命名 / level 0 / parent NULL / order 0`；
2. 其余文件夹从 `0002` 起按深度优先重新编号；
3. 根级顺序：按旧 `sort_order` 升序，相同则按名称；排序号从 1 开始重新分配；
4. 子级顺序同理，父级先于子级分配编号；
5. 写入 `Folder_Level`、`Folder_Parent_ID`、`Folder_Parent_Name`、`Folder_Order`；
6. 同步更新 `notes.folder_id`：旧 ID → 新 ID；旧 `uncategorized` → `0001`；
7. 嵌套超过 3 层或编号超过 9999 时中止并报错；
8. 新旧文件夹数量不一致视为存在循环引用，中止迁移；
9. 以上步骤在单个事务内完成，最后 `DROP TABLE folders`。

迁移日志：`[Notepad] 文件夹表迁移完成: N 个文件夹 -> Note_Folders`。

### 默认文件夹保障

`ensure_default_folder()`：

```sql
INSERT OR IGNORE INTO Note_Folders (...) VALUES ('0001', '未命名', '0', NULL, NULL, '0', ...);
```

即使没有旧表，也会保证 `0001` 存在。无归属或指向不存在文件夹的笔记由随后执行的 `refresh_note_paths()` 归入「未命名」。

### 迁移旧 `notes` 表

触发条件：`sqlite_master` 中存在名为 `notes` 的表。

数据来源：`documents d JOIN notes n ON n.document_id = d.id`。

规则：

1. 按 `documents.created_at` 升序重新分配 `Note_ID`（`0000000001` 起，十位补零）；
2. 标题、正文、标签、置顶、创建/更新/删除时间、`device_id`、`version` 原样迁移；标题超过 20 个字符时截断并写警告日志；
3. 按旧 `folder_id` 解析并写入 `Is_Folder` + `Folder1~3`，找不到文件夹时归入默认文件夹；
4. 先 `DROP TABLE notes`（旧表通过外键引用 `documents(id)`），再删除 `documents` 中 `type='note'` 的记录；
5. 以上步骤在单个事务内完成，失败整体回滚，下次启动重试。

迁移日志：`[Notepad] 笔记表迁移完成: N 条 -> Note_Content`。

### 文件夹路径重建

`refresh_note_paths()` 会遍历 `Note_Content`，从 `Is_Folder` + 对应 `FolderN` 反推当前文件夹，再沿 `Note_Folders` 父链重新生成三级路径。删除文件夹（笔记移到父级、子文件夹整体上移）后必须调用，保证冗余路径与实际层级一致。

## 5.5 数据目录与文件

路径解析在 `src-tauri/src/platform/paths.rs`：

| 场景 | 数据目录 |
|---|---|
| 环境变量 `MYSYSTEM_DATA_DIR` | 直接使用该路径（最高优先级） |
| 开发模式（debug，非 Android） | `CARGO_MANIFEST_DIR/../data`，即项目根 `data/` |
| 发布模式（非 Android） | `exe 所在目录/data`；不可写时回退 `app_data_dir()/data` |
| Android | `app_data_dir()/data` |

目录内容：

```
data/
├── mydata.db          # SQLite 数据库
├── mydata.db-wal      # 可能存在的 WAL 文件
├── mydata.db-shm      # 可能存在的共享内存文件
├── books/             # 导入的书籍，文件名为 <uuid>.<ext>
└── log/
    └── mysystem-YYYY-MM-DD.log
```

- `books_dir()`、`log_dir()` 会自动创建目录；
- `delete_book_file` 只允许删除 canonicalize 后位于 `books/` 内的文件，防止误删外部文件；
- asset 协议在启动时动态授权 `<data>` 目录，供 WebView 读取书籍。

## 5.6 数据操作约定

### 软删除

| 对象 | 操作 | 实现 |
|---|---|---|
| 笔记 | `delete_note` | `Note_Content.Delete_Time = now, Update_Time = now` |
| 书籍 | `delete_book` | `Read_Books.Delete_Time = now, Update_Time = now, Version + 1`；同事务级联软删除其标注 |
| 标注 | `delete_annotation` | `Read_Annotation.Delete_Time = now, Update_Time = now, Version + 1`；影响行数为 0 时报「标注不存在」 |
| 文件夹 | `delete_folder` | 物理 `DELETE`，并重排子文件夹与笔记路径 |

笔记查询过滤 `Note_Content.Delete_Time IS NULL`；书籍/标注查询过滤各自表的 `Delete_Time IS NULL`。

### 版本与设备

- `Read_Books.Version` / `Device_ID` 与 `Read_Annotation.Version` / `Device_ID` 记录最后写入设备：创建时 `Version = 1`，更新与删除时 `Version + 1` 并写入当前设备；
- `Note_Content.Version` / `Device_ID` 规则相同；
- 笔记、书籍、标注的同步均已暂停（编号各设备独立自增），版本号暂不参与冲突合并。

### 字段更新语义

- Rust 输入结构中的 `Option<T>` 表示“未提供”，`None` 不更新该字段；
- 因此 `update_note` 无法通过 `folderId: null` 把笔记移出文件夹（前端也不会这样调用，移动总是选择具体文件夹）；
- `is_pinned` 使用 `Option<bool>`，JSON 传 `false` 可以取消置顶。

## 5.7 备份、查看与恢复

- 备份：退出应用后复制整个 `data/` 目录。
- 如果目录下存在 `mydata.db-wal` / `mydata.db-shm`，说明有未合并的 WAL 数据，复制时要**三个文件一起复制**，否则可能丢失最近写入。
- 命令行查看：

```bash
sqlite3 data/mydata.db ".tables"
sqlite3 data/mydata.db "SELECT Folder_ID, Folder_Name, Folder_Level, Folder_Parent_ID, Folder_Order FROM Note_Folders ORDER BY CAST(Folder_Order AS INTEGER);"
sqlite3 data/mydata.db "SELECT Note_ID, Note_Title, Is_Folder, Folder1, Folder2, Folder3, Is_Pinned FROM Note_Content WHERE Delete_Time IS NULL ORDER BY Update_Time DESC LIMIT 20;"
sqlite3 data/mydata.db "SELECT Book_ID, Book_Title, File_Format, Total_Pages, Book_Hash FROM Read_Books WHERE Delete_Time IS NULL ORDER BY Create_Time DESC;"
```

- 恢复：退出应用，用备份替换 `data/` 内容后重启。
- 不建议在应用运行时直接修改数据库；如需操作，先关闭应用。
