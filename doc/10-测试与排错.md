# 10 测试与排错

## 10.1 当前测试现状

- 未配置单元测试、集成测试、E2E 测试；
- 未配置 ESLint/Prettier；
- 唯一的自动化检查：
  - 前端：`pnpm build` 中的 `vue-tsc --noEmit`；
  - 后端：`cargo check`（只做编译检查，不运行测试）。

因此功能验证以手工测试为主。修改核心逻辑（尤其文件夹迁移、同步合并）时，建议临时编写 Rust 单元测试或使用数据库副本验证，验证后删除临时测试代码。

## 10.2 静态检查命令

```bash
pnpm build
cd src-tauri && cargo check
```

要求：两者均无错误。TypeScript 开启了 `strict`、`noUnusedLocals`、`noUnusedParameters`、`noFallthroughCasesInSwitch`，未使用的变量也会报错。

## 10.4 常见问题

### 前端 invoke 报 “command not found”

原因：命令未注册，或命令名拼写错误。

处理：

1. 检查 `src-tauri/src/commands.rs` 的 `invoke_handler()` 是否包含该命令；
2. 检查 `#[tauri::command]` 是否在 `pub fn` 上；
3. 修改后重启 `pnpm tauri dev`（Rust 需要重新编译）。

### 参数反序列化失败

- 前端参数名必须是 camelCase（`deviceId`、`folderId`、`filePath`）；
- Rust 结构体必须有 `#[serde(rename_all = "camelCase")]`；
- 可选字段传 `undefined` 等同于未提供，传 `null` 需要 Rust 端为 `Option<T>`。

### 文件夹树显示错误 / 删文件夹后子文件夹跑到根级

原因：前端 `folders` 缓存仍保留被删文件夹的 `parentId`，`buildFolderTree` 把找不到父级的节点当作根级。

处理：删除后必须 `await store.fetchFolders()` 重新拉取。参考 `stores/notepad.ts` 的 `removeFolder`。

### 点击删除确认框的「取消」仍然删除

原因：Tauri WebView 中 `window.confirm` 可能错误返回 `true`。

处理：统一使用 `platform/services/dialog.ts` 的 `confirmAction`（Tauri dialog 插件）。不要新增 `window.confirm`。

### 新增模块后导航不出现

- `import.meta.glob` 在 Vite 启动时展开，需要重启 `pnpm dev`；
- 检查 `index.ts` 是否默认导出、`id` 是否为空、`enabled` 是否禁用了当前平台；
- 查看 `[ModuleLoader]` 日志。

### 书籍打不开 / 资源 403

- 确认文件位于 `<data>/books` 或被动态授权的 `<data>` 下；
- `convertFileSrc` 生成的 URL 需要 CSP 允许 `asset:`；
- 发布版数据目录可能回退到 `%APPDATA%`，确认实际路径（设置页/日志）；
- 外部路径未导入时可能不可读，建议总是通过「导入书籍」复制到 `data/books`。

### PDF 中文缺字

- PDF 组件从 `https://unpkg.com/pdfjs-dist@.../cmaps/` 加载 cMap，需要网络；
- 离线环境应把 cMap 放到本地并通过 `cMapUrl` 指向本地路径；
- 同时检查 CSP 是否允许对应请求。

### EPUB 一直加载 / 超时

- 组件对 `book.ready` 15s、首次渲染 15s、目录 5s 设置了超时；
- 大文件或损坏文件会显示错误遮罩；
- 检查日志 `[EPUB] 加载失败`；
- 确认文件扩展名与实际格式一致。

### TXT 乱码

- 解码顺序：BOM → UTF-8 → GBK → UTF-8 回退；
- 非 UTF-8/GBK 编码（如 Big5）可能乱码，需要扩展 `decodeText`；
- 章节识别依赖「第 X 章/节/回」且长度 < 40，格式特殊时可能只识别为「序章」。

### 数值键一次翻两页

PDF/TXT 子组件与阅读页父组件都绑定了方向键，可能重复处理。可在父组件只对 EPUB 绑定，或移除子组件监听。属于已知问题，见 [11-已知偏差与路线图.md](11-已知偏差与路线图.md)。

### 同步扫描不到设备

- 两台设备是否在同一网段；
- 对方是否开启「接收同步请求」；
- Windows 防火墙是否允许 UDP 54321；
- 路由器是否开启 AP 隔离；
- 端口是否被其他程序占用（日志 `[Discovery] 绑定发现端口失败`）。

### 同步后数据没有变化

- 当前只同步 `documents`（不含 `type='note'`），笔记、文件夹、书籍、标注都不同步；
- 合并只在对方 `updated_at` 严格更新时覆盖；时间相同会被拒绝；
- 检查双方系统时间是否准确；
- 查看同步日志的新增/合并/拒绝计数。

### 数据库被锁 / 无法打开

- 应用运行时不要用其他工具直接写数据库；
- 复制数据库到临时目录再查看；
- 若存在 `-wal` / `-shm`，三个文件一起复制。

### 日志没有写入文件

- 日志初始化失败时只输出到终端，不阻塞启动；
- 检查 `<data>/log` 是否可写；
- 日志初始化发生在 `setup` 最前面，之后的日志才会落盘。

## 10.5 日志定位

日志格式：

```
[2026-10-21 17:20:01.123] [INFO] [Notepad] 新建笔记: 标题 (0000000001)
```

常用检索：

```bash
grep "\[ERROR\]" data/log/mysystem-*.log
grep "\[Sync\]" data/log/mysystem-*.log
grep "\[HTTP\]" data/log/mysystem-*.log
grep "\[ModuleLoader\]" data/log/mysystem-*.log
```

前端日志通过 `write_log` 写入同一文件，前缀通常是 `[UI]`、`[Router]`、`[Notepad]`、`[Reader]`、`[Sync]`。

## 10.6 数据库检查

关闭应用后：

```bash
sqlite3 data/mydata.db
.tables
.schema Note_Folders
.schema Note_Content
SELECT Folder_ID, Folder_Name, Folder_Level, Folder_Parent_ID, Folder_Order
  FROM Note_Folders ORDER BY CAST(Folder_Order AS INTEGER);
SELECT Note_ID, Note_Title, Is_Folder, Folder1, Folder2, Folder3, Is_Pinned
  FROM Note_Content WHERE Delete_Time IS NULL;
```

检查要点：

- 是否只有一个 `0001 / 未命名 / level 0`；
- 是否存在 `Folder_Parent_ID` 指向不存在记录；
- `Folder_Level` 是否在 0–3；
- 笔记 `Folder1~3` 指向的文件夹是否都存在，且 `Is_Folder` 与最后一列非空的位置一致；
- 是否有重复 `(Folder_Name, Folder_Level, parent)`。

## 10.7 性能与稳定性注意

- 搜索使用 `LIKE '%...%'`，数据量大时无索引可用，后续可考虑 FTS5。
- 同步为全量 payload，文档很多时请求体大、耗时长（客户端超时 30s）；
- 每次操作都新建 SQLite 连接，当前数据量下可接受，后续可考虑连接复用。
- EPUB 标注高亮保存在 runtime 的 `appliedHighlights` Set 中，重新加载后重新渲染。
