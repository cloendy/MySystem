# 02 系统架构

## 2.1 总体结构

```
┌──────────────────────────────────────────────────────────────┐
│                        Tauri 应用                             │
│                                                              │
│  ┌────────────────────── WebView（Vue 3）──────────────────┐  │
│  │  AppShell（Windows） / MobileShell（Android）            │  │
│  │    ├─ 平台外壳：导航、设置、首页                          │  │
│  │    ├─ 模块路由：/{moduleId}/...                          │  │
│  │    └─ src/modules/notepad、reader                        │  │
│  │         视图 → Pinia store → 模块 api.ts                  │  │
│  └───────────────────────────┬─────────────────────────────┘  │
│                              │ invoke（Tauri IPC）            │
│  ┌───────────────────────────▼─────────────────────────────┐  │
│  │  Rust：commands.rs（统一注册 43 个命令）                  │  │
│  │    ├─ platform/：paths、logger、storage、config、        │  │
│  │    │             discovery、http_server/client、sync     │  │
│  │    └─ modules/：notepad、reader                          │  │
│  └───────────────────────────┬─────────────────────────────┘  │
│                              │ rusqlite / std::fs            │
│                     <应用根>/data/                            │
│                     ├─ mydata.db                              │
│                     ├─ books/                                 │
│                     └─ log/                                   │
└──────────────────────────────────────────────────────────────┘
```

架构原则：

1. **平台与业务分离**：`src/platform/` 与 `src-tauri/src/platform/` 不依赖具体业务；业务模块可以依赖平台，反之不允许。
2. **模块自包含**：前端模块包含自己的路由、视图、store、API 封装和类型；Rust 侧按相同模块 id 建目录。
3. **单一组装层**：Rust 命令只在 `commands.rs` 注册一次；前端路由只在模块 `index.ts` 声明一次。
4. **数据入口唯一**：所有业务数据落到 `<应用根>/data/mydata.db`，路径统一由 `platform/paths.rs` 解析。
5. **日志入口唯一**：Rust 用 `log_*!` 宏，前端用 `platform/services/logger.ts`。

## 2.2 前端启动流程

入口链路：`index.html` → `src/main.ts` → `src/App.vue`。

1. `main.ts`
   - 创建 Vue 应用，安装 Pinia；
   - 调用 `createAppRouter()` 创建全局单例 router（hash 模式），注册 `/` 与 `/settings` 基础路由；
   - 调用 `installUiLogging()` 安装全局点击日志；
   - 加载 `style.css` 与 `styles/common.css`；
   - 挂载 `#app`。
2. `App.vue` 的 `onMounted`
   - `detectPlatform()`：根据 userAgent 判断 `windows` / `android`；
   - `loadEnabledModules(platform)`：通过 `import.meta.glob` 自动发现并加载模块；
   - `registerModuleRoutes(modules)`：把模块路由加上 `/{moduleId}` 前缀注册；
   - 默认跳转到 `order` 最小的模块（`/{id}/`）；
   - 按平台渲染 `AppShell` 或 `MobileShell`；加载完成前显示“加载中...”。
3. 路由切换由 `router.afterEach` 写入 `[Router] 页面切换: A -> B`。

## 2.3 模块机制

### 模块契约

`src/platform/services/module-types.ts` 定义 `ModuleInterface`：

```ts
export interface ModuleInterface {
    id: string;
    name: string;
    version: string;
    icon?: string;
    order?: number;
    enabled?: Partial<Record<'windows' | 'android', boolean>>;
    onLoad(context: ModuleContext): Promise<void>;
    onUnload?(): Promise<void>;
    onActivate?(): void;
    onDeactivate?(): void;
    getRoutes(): ModuleRoute[];
    onSearch?(query: string): Promise<SearchResult[]>;
}
```

`ModuleContext` 当前只注入 `platform` 与 `events`（事件总线）。

### 自动发现

`platform/services/module-loader.ts` 使用：

```ts
const moduleEntries = import.meta.glob<{ default: ModuleInterface }>(
    '../../modules/*/index.ts'
);
```

加载规则：

- 只识别 `src/modules/<id>/index.ts` 的默认导出；
- 校验 `id`、`onLoad`、`getRoutes` 是否存在；
- 重复 `id` 跳过并写警告；
- `enabled[platform] === false` 时跳过；未声明默认启用；
- `onLoad` 失败时记录错误并跳过该模块；
- 最终按 `order` 升序排序（未声明按 0）。

> `import.meta.glob` 在 Vite 启动时展开，新增/删除模块目录后需重启 `pnpm dev`。

### 路由注册

`platform/router/index.ts` 把每个模块路由映射为：

- 路径：`/{moduleId}` + 模块内路径（模块内写 `/`，结果为 `/notepad/`）；
- 名称：`{moduleId}:{route.name}`；
- `meta`：附加 `moduleId`、`moduleName`。

当前路由：

| 路径 | 名称 | 页面 |
|---|---|---|
| `/` | `home` | 平台首页（模块列表） |
| `/settings` | `settings` | 设置页 |
| `/notepad/` | `notepad:note-list` | 笔记列表 |
| `/notepad/edit/:id` | `notepad:note-edit` | 笔记编辑 |
| `/reader/` | `reader:bookshelf` | 书架 |
| `/reader/book/:id` | `reader:book-reader` | 阅读页 |

## 2.4 Rust 后端

### 启动顺序（`src/lib.rs`）

1. 注册 `tauri_plugin_fs`、`tauri_plugin_dialog`；
2. `setup`：
   - `platform::logger::init`（必须最先，保证后续日志落盘）；
   - `platform::database_init::init_database`：执行全部 `CREATE TABLE IF NOT EXISTS`；
   - `modules::notepad::init`：迁移旧文件夹表 → 确保「未命名」存在 → 迁移旧笔记表到 `Note_Content` → 重建笔记文件夹路径；
   - 授权 asset 协议访问 `<data>` 目录（书籍文件预览）；
3. 挂载 `commands::invoke_handler()`；
4. 运行应用，退出时记录 `应用退出`。

`src/main.rs` 只保留 `windows_subsystem` 属性并调用 `mysystem_lib::run()`。`#[cfg_attr(mobile, tauri::mobile_entry_point)]` 在 `lib.rs` 上，Android 复用同一入口。

### 命令注册

所有命令在 `src-tauri/src/commands.rs` 的 `invoke_handler()` 中通过 `tauri::generate_handler!` 注册，分四组：

1. 平台：路径与日志（5）；
2. 平台：文档基础 CRUD（5）；
3. 平台：配置（3）；
4. 平台：局域网发现与同步（9）；
5. 记事本（10）；
6. 阅读器（11）。

合计 **43** 个命令，完整清单见 [07-开发API.md](07-开发API.md)。

### 数据访问

- 每个模块/服务自己 `Connection::open(db_path)`，没有全局连接池；
- 需要多表一致性时使用 `conn.transaction()`；
- 阅读器扩展表 `books` / `annotations` 与 `documents` 通过 `document_id` 关联，查询基本是 `INNER JOIN`；
- 记事本笔记使用独立的 `Note_Content` 表，不参与 `documents` 关联；文件夹路径（`Is_Folder` + `Folder1~3`）冗余在笔记行内；
- 删除业务对象采用软删除（文档写 `deleted_at`、笔记写 `Delete_Time`），查询统一过滤未删除记录。

## 2.5 日志架构

```
Rust 业务 ──log_info!/log_warn!/log_error!/log_debug!──┐
                                                     ├─► 终端 + data/log/mysystem-YYYY-MM-DD.log
前端业务 ──logger.info/warn/error/debug──invoke──► write_log ─┘
```

- Rust：`platform/logger.rs`，按天分文件，格式 `[YYYY-MM-DD HH:mm:ss.SSS] [LEVEL] message`；
- 前端：`platform/services/logger.ts`，底层调用 `write_log`；
- UI 点击：`platform/services/ui-logging.ts` 捕获阶段委托，300ms 内同路由同标签去重，`data-log-ignore` 可跳过；
- 路由切换：`router.afterEach` 自动记录；
- 日志查看：`read_log_file` 单文件最多读最后 512KB，拒绝路径穿越和非 `.log` 文件。

## 2.6 事件与跨组件通信

| 机制 | 位置 | 用途 |
|---|---|---|
| `EventBus` | `platform/services/event-bus.ts` | 平台注入模块的通用事件总线，目前业务未大量使用 |
| `mysystem:sync-completed` | `window` CustomEvent | 同步完成后刷新书架、笔记列表与文件夹 |
| `mysystem:annotation-added` | `window` CustomEvent | EPUB 保存标注后刷新标注面板 |
| Pinia store | 各模块 `stores/` | 同模块内共享状态 |

## 2.7 同步架构

```
发起方                                      接收方
  │ get_sync_payload（本地全量）               │
  │ ── POST /api/sync/exchange ─────────────► │ merge_payload（按 updated_at 合并）
  │                                           │ read_local_payload
  │ ◄──────────── SyncResponse ────────────── │
  │ apply_local_payload（合并 serverPayload）  │
```

- 发现：UDP 54321 广播 `discover`，监听方回复 `announce`；
- 握手：`GET /api/info`，返回设备 id/名称/平台/协议版本；
- 交换：`POST /api/sync/exchange`，JSON 全量 payload；
- 合并规则：本地没有则插入；`updated_at` 更新则覆盖；相等或更旧则拒绝；
- 当前 payload 只含非 `note` 类型的 `documents`（笔记、文件夹、书籍、标注均不同步），`notes` 字段固定为空以兼容旧客户端。

详见 [07-开发API.md](07-开发API.md) 与 [03-功能设计.md](03-功能设计.md)。

## 2.8 目录职责对照

| 路径 | 职责 |
|---|---|
| `src/platform/shell/` | `AppShell.vue`、`MobileShell.vue`、`HomeView.vue`、`SettingsView.vue` |
| `src/platform/shell/settings/` | 同步设置共享状态 `useSyncSettings.ts` 与子组件 |
| `src/platform/services/` | 模块加载、路由、日志、设备 ID、配置/同步 invoke、事件总线、确认弹窗 |
| `src/modules/<id>/` | `index.ts`、`api.ts`、`types.ts`、`stores/`、`views/`、`components/`、`composables/` |
| `src-tauri/src/platform/` | 路径、建表、日志、配置、发现、HTTP 服务端/客户端、同步 payload、基础文档 CRUD |
| `src-tauri/src/modules/` | 业务模块 Rust 实现，目录 id 与前端一致 |
| `src-tauri/src/commands.rs` | 唯一命令注册点 |
| `src-tauri/src/models/` | 跨模块基础模型（`BaseDocument` 等） |
| `data/` | 运行时数据库、书籍文件、日志 |

## 2.9 扩展点

| 扩展需求 | 落点 |
|---|---|
| 新增业务模块 | `src/modules/<id>/index.ts` + `src-tauri/src/modules/<id>/` + 命令注册 |
| 新增数据表 | `src-tauri/src/platform/database_init.rs` |
| 新增平台服务 | `src/platform/services/` 与/或 `src-tauri/src/platform/` |
| 新增同步字段 | `platform/sync_payload.rs` + 前端 `config.ts` 类型 + 合并逻辑 |
| 全局搜索 | 实现模块 `onSearch`，接入 `AppShell` 搜索框 |
