# 06 数据结构

本章列出 Rust 与 TypeScript 之间的数据契约、枚举取值、序列化约定，以及配置、事件等非数据库结构。

## 6.1 通用约定

| 约定 | 说明 |
|---|---|
| 命名 | Rust 字段 `snake_case` + `#[serde(rename_all = "camelCase")]`；前端使用 camelCase |
| 时间 | 笔记、配置为 Unix 毫秒，Rust `i64` / TS `number`；书籍、标注为 UTC 时间文本（`YYYY-MM-DD HH:MM:SS.mmm`），Rust `String` / TS `string` |
| ID | 笔记、书籍、标注为十位补零编号字符串（`0000000001` 起）；文件夹为四位编号字符串 |
| 可空 | Rust `Option<T>` ↔ TS `T \| null`；缺省字段用 `Option` 表示“未提供” |
| 布尔 | Rust 返回 `bool`；数据库中文档用 `INTEGER` 0/1，笔记用 `CHAR(1)` `'0'`/`'1'` |
| 数组/对象 | 标签存 JSON 字符串；标注定位 `position` 存 JSON 字符串 |
| 错误 | Rust 命令返回 `Result<T, String>`，前端收到 rejected Promise，字符串为中文错误信息 |
| 命令参数 | 前端 invoke 使用 camelCase 键（如 `deviceId`），Tauri 自动映射到 Rust snake_case 参数 |

## 6.2 文档与笔记

### Rust（`modules/notepad/mod.rs`）

```rust
pub struct Note {
    pub id: String,
    pub title: String,
    pub content: String,
    pub tags: Vec<String>,
    pub folder_id: Option<String>,
    pub is_pinned: bool,
    pub created_at: i64,
    pub updated_at: i64,
    pub deleted_at: Option<i64>,
    pub device_id: String,
    pub version: i64,
}

pub struct CreateNoteInput {
    pub title: String,
    pub content: Option<String>,
    pub folder_id: Option<String>,
    pub tags: Option<Vec<String>>,
    pub device_id: String,
}

pub struct UpdateNoteInput {
    pub id: String,
    pub title: Option<String>,
    pub content: Option<String>,
    pub folder_id: Option<String>,
    pub tags: Option<Vec<String>>,
    pub is_pinned: Option<bool>,
    pub device_id: String,

```

### TypeScript（`modules/notepad/types.ts`）

```ts
export interface Note {
    id: string;
    title: string;
    content: string;
    tags: string[];
    folderId: string | null;
    isPinned: boolean;
    createdAt: number;
    updatedAt: number;
    deletedAt: number | null;
    deviceId: string;
    version: number;
}

export interface CreateNoteInput {
    title: string;
    content?: string;
    folderId?: string | null;
    tags?: string[];
}

export interface UpdateNoteInput {
    id: string;
    title?: string;
    content?: string;
    folderId?: string | null;
    tags?: string[];
    isPinned?: boolean;
}
```

> 前端输入类型不包含 `deviceId`，由模块 `api.ts` 调用 `getDeviceId()` 自动注入；Rust 侧写入 `Note_Content.Device_ID`。

### 字段语义

| 字段 | 语义 |
|---|---|
| `id` | `Note_ID`，十位补零字符串，由后端生成 `MAX+1` |
| `title` | 最多 20 个字符，后端校验，超出返回错误；可为空字符串，列表显示「无标题」 |
| `tags` | 去重由前端保证；后端原样存 JSON |
| `folderId` | 由 `Is_Folder` + `FolderN` 计算；新建时未指定则后端设为 `0001`；更新时 `null` 视为不修改 |
| `isPinned` | 数据库存 `'0'`/`'1'`，API 层为布尔；列表排序第一优先级 |
| `deletedAt` | 非空即已软删除，正常查询不会返回 |
| `deviceId` | 最后写入设备；创建时写入，更新/删除时覆盖 |
| `version` | 创建时为 1，每次更新/删除 +1；当前仅记录，不参与合并 |

## 6.3 文件夹

### Rust（`modules/notepad/folders.rs`）

```rust
pub struct Folder {
    pub id: String,
    pub name: String,
    pub parent_id: Option<String>,
    pub sort_order: i64,
}

pub struct CreateFolderInput {
    pub name: String,
    pub parent_id: Option<String>,
}

pub struct UpdateFolderInput {
    pub id: String,
    pub name: String,
}
```

注意：`Folder` 不返回 `level` 和 `parent_name`；前端根据 `parentId` 链自行计算层级。

### TypeScript

```ts
export interface Folder {
    id: string;
    name: string;
    parentId: string | null;
    sortOrder: number;
}

export interface FolderNode extends Folder {
    children: FolderNode[];
    level: number;   // 根级用户文件夹为 1
}
```

### 前端派生结构与工具

`modules/notepad/folders.ts`：

- `buildFolderTree(folders): FolderNode[]`：组装树、计算层级、排序；父节点缺失/环按根级；
- `flattenFolderTree(nodes): FolderNode[]`：按树顺序展开，用于移动菜单；
- `isDescendantOf(folders, id, ancestorId)`：判断祖先关系，用于新建输入框定位。

### TypeScript（`modules/reader/types.ts`）

```ts
export interface Book {
    id: string;
    title: string;
    author: string;
    coverUrl: string;
    filePath: string;
    fileFormat: 'epub' | 'pdf' | 'mobi' | 'txt';
    /** 源文件内容 SHA-256（用于导入去重，旧数据可能为空） */
    hash: string;
    totalPages: number;
    currentPage: number;
    readingStatus: 'unread' | 'reading' | 'finished';
    /** UTC 时间文本，`YYYY-MM-DD HH:MM:SS.mmm` */
    createdAt: string;
    updatedAt: string;
    deletedAt: string | null;
    version: number;
    deviceId: string;
}

export interface Annotation {
    id: string;
    bookId: string;
    text: string;
    note: string;
    page: number;
    position: string;   // JSON 字符串，见 6.5 的三种格式
    color: string;
    /** UTC 时间文本，`YYYY-MM-DD HH:MM:SS.mmm` */
    createdAt: string;
    updatedAt: string;
    deletedAt: string | null;
    version: number;
    deviceId: string;
}
```

输入类型：`CreateBookInput`、`UpdateBookInput`、`CreateAnnotationInput`，同样由 `api.ts` 注入 `deviceId`。

> 书籍与标注的时间字段直接使用数据库 `DATETIME` 的 UTC 文本（`YYYY-MM-DD HH:MM:SS.mmm`），字符串排序即时间排序；前端展示本地时间时需自行解析。迁移旧阅读器表时，旧的毫秒时间戳会转换为该格式。

## 6.5 枚举与字符串取值

| 字段 | 取值 | 说明 |
|---|---|---|
| `Read_Books.File_Format` | `epub` / `pdf` / `mobi` / `txt` | 导入仅接受这四种；阅读仅支持前三种 |
| `Read_Books.Reading_Status` | `unread` / `reading` / `finished` | 初始 `unread`；PDF/TXT 阅读后更新 |
| `Read_Books.Book_Hash` | 64 位十六进制 | 源文件 SHA-256；旧数据迁移后为空 |
| `Read_Annotation.Color` | 默认 `#FFEB3B`；可选 `#A5D6A7` / `#90CAF9` / `#F48FB1` | 三种格式共用气泡四色 |
| `Read_Annotation.Position` | `{"cfi"}` / `{"page","rects","text"}` / `{"chapter","start","end","text"}` | 依次对应 EPUB / PDF / TXT |
| `enabled` 平台键 | `windows` / `android` | 模块启用开关 |

## 6.6 设备标识

设备 ID 通过 `src/platform/services/device.ts` 的 `getDeviceId()` 获取：读取 `localStorage` 键 `mysystem_device_id`，不存在时生成 UUID v4 并持久化。

- 设备 ID 只用于写入各业务表的 `Device_ID` 字段（`Note_Content` / `Read_Books` / `Read_Annotation`），记录最后写入设备；
- 当前没有局域网设备发现、设备信息交换或网络设备模型。

## 6.7 配置与本地存储

### `app_config` 键

`app_config` 表作为通用键值配置能力保留（Rust `get_config` / `set_config`，前端 `getConfig` / `setConfig`）。当前应用没有内置配置键。

### `localStorage`

| 键 | 值 | 写入方 |
|---|---|---|
| `mysystem_device_id` | UUID v4 | `platform/services/device.ts` |
| `mysystem_notepad_editor_mode` | `'markdown'` / `'text'` | 笔记编辑页 |
| `epub_pos_<bookId>` | EPUB CFI 字符串 | `EpubReader.vue` |

## 6.8 前端事件

| 事件 | 载体 | 载荷 | 触发方 / 监听方 |
|---|---|---|---|
| `mysystem:annotation-added` | `window` CustomEvent | `Annotation` | EPUB/PDF/TXT 保存标注后触发；`AnnotationPanel` 刷新 |

`EventBus`（`ModuleContext.events`）提供 `on` / `off` / `emit`，当前业务代码主要使用上面的 window 事件。

## 6.9 前后端类型对照速查

| 概念 | Rust | TypeScript |
|---|---|---|
| 笔记 | `Note` | `Note` |
| 新建笔记 | `CreateNoteInput` + `device_id` | `CreateNoteInput`（无 deviceId） |
| 更新笔记 | `UpdateNoteInput` + `device_id` | `UpdateNoteInput` |
| 文件夹 | `Folder` | `Folder` / `FolderNode` |
| 书籍 | `Book` | `Book` |
| 标注 | `Annotation` | `Annotation` |
| 日志文件 | `LogFileInfo` | 前端 `LogFileInfo`（logger.ts） |

新增字段时，必须同时修改 Rust 结构体、数据库列（如需要）、前端类型与 `api.ts` 封装，否则序列化会丢字段或类型检查失败。
