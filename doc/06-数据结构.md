# 06 数据结构

本章列出 Rust 与 TypeScript 之间的数据契约、枚举取值、序列化约定，以及同步、配置、事件等非数据库结构。

## 6.1 通用约定

| 约定 | 说明 |
|---|---|
| 命名 | Rust 字段 `snake_case` + `#[serde(rename_all = "camelCase")]`；前端使用 camelCase |
| 时间 | Unix 毫秒，Rust `i64` / TS `number` |
| ID | 文档、书籍、标注、同步操作为 UUID v4；笔记为十位补零编号字符串（`0000000001` 起）；文件夹为四位编号字符串 |
| 可空 | Rust `Option<T>` ↔ TS `T \| null`；缺省字段用 `Option` 表示“未提供” |
| 布尔 | Rust 返回 `bool`；数据库中文档用 `INTEGER` 0/1，笔记用 `CHAR(1)` `'0'`/`'1'` |
| 数组/对象 | 标签存 JSON 字符串；标注定位 `position` 存 JSON 字符串 |
| 错误 | Rust 命令返回 `Result<T, String>`，前端收到 rejected Promise，字符串为中文错误信息 |
| 命令参数 | 前端 invoke 使用 camelCase 键（如 `deviceId`），Tauri 自动映射到 Rust snake_case 参数 |

## 6.2 文档与笔记

### Rust（`modules/notepad/mod.rs`）

```rust

    pub id: String,

```

### TypeScript（`modules/notepad/types.ts`）

```ts
export interface Note {
    id: string;
    title: string;
    content: string;
    tags: string[];
    folderId: string | null;
    isPinned: boolean;
    createdAt: number;
    updatedAt: number;
    deletedAt: number | null;
    deviceId: string;
    version: number;
}

export interface CreateNoteInput {
    title: string;
    content?: string;
    folderId?: string | null;
    tags?: string[];
}

export interface UpdateNoteInput {
    id: string;
    title?: string;
    content?: string;
    folderId?: string | null;
    tags?: string[];
    isPinned?: boolean;
}
```

> 前端输入类型不包含 `deviceId`，由模块 `api.ts` 调用 `getDeviceId()` 自动注入；Rust 侧写入 `Note_Content.Device_ID`，并同时写 `sync_operations` 日志。

### 字段语义

| 字段 | 语义 |
|---|---|
| `id` | `Note_ID`，十位补零字符串，由后端生成 `MAX+1` |
| `title` | 最多 20 个字符，后端校验，超出返回错误；可为空字符串，列表显示「无标题」 |
| `tags` | 去重由前端保证；后端原样存 JSON |
| `folderId` | 由 `Is_Folder` + `FolderN` 计算；新建时未指定则后端设为 `0001`；更新时 `null` 视为不修改 |
| `isPinned` | 数据库存 `'0'`/`'1'`，API 层为布尔；列表排序第一优先级 |
| `deletedAt` | 非空即已软删除，正常查询不会返回 |
| `deviceId` | 最后写入设备；创建时写入，更新/删除时覆盖 |
| `version` | 创建时为 1，每次更新/删除 +1；笔记同步停用期间不参与合并 |

注意：`Folder` 不返回 `level` 和 `parent_name`；前端根据 `parentId` 链自行计算层级。

### TypeScript

```ts
export interface Folder {
    id: string;
    name: string;
    parentId: string | null;
    sortOrder: number;
}

export interface FolderNode extends Folder {
    children: FolderNode[];
    level: number;   // 根级用户文件夹为 1
}
```

### 前端派生结构与工具

`modules/notepad/folders.ts`：

- `buildFolderTree(folders): FolderNode[]`：组装树、计算层级、排序；父节点缺失/环按根级；
- `flattenFolderTree(nodes): FolderNode[]`：按树顺序展开，用于移动菜单；
- `isDescendantOf(folders, id, ancestorId)`：判断祖先关系，用于新建输入框定位。

## 6.5 枚举与字符串取值

| 字段 | 取值 | 说明 |
|---|---|---|
| `documents.type` | `note` / `book` / `annotation` | 标注的 title 为标注文本 |
| `books.file_format` | `epub` / `pdf` / `mobi` / `txt` | 导入仅接受这四种；阅读仅支持前三种 |
| `books.reading_status` | `unread` / `reading` / `finished` | 初始 `unread`；PDF/TXT 阅读后更新 |
| `annotations.color` | 默认 `#FFEB3B`；可选 `#A5D6A7` / `#90CAF9` / `#F48FB1` | EPUB 气泡四色 |
| `sync_operations.operation` | `create` / `update` / `delete` | 只写不读 |
| `enabled` 平台键 | `windows` / `android` | 模块启用开关 |

## 6.7 同步数据结构

### Rust（`platform/sync_payload.rs`）

```rust
pub struct DocumentPayload {
    pub id: String,
    pub r#type: String,
    pub title: String,
    pub created_at: i64,
    pub updated_at: i64,
    pub deleted_at: Option<i64>,
    pub version: i64,
    pub device_id: String,
}

pub struct NotePayload {
    pub document_id: String,
    pub content: String,
    pub tags: String,          // JSON 数组字符串
    pub folder_id: Option<String>,
    pub is_pinned: i64,        // 0/1
}

pub struct SyncPayload {
    pub documents: Vec<DocumentPayload>,
    pub notes: Vec<NotePayload>,
    pub sender_device_id: String,
    pub sender_device_name: String,
}

pub struct SyncResponse {
    pub accepted: usize,
    pub rejected: usize,
    pub merged: usize,
    pub server_payload: SyncPayload,
}
```

### TypeScript（`platform/services/config.ts`）

```ts
export interface SyncPayload {
    documents: Array<{
        id: string;
        type: string;
        title: string;
        createdAt: number;
        updatedAt: number;
        deletedAt: number | null;
        version: number;
        deviceId: string;
    }>;
    notes: Array<{
        documentId: string;
        content: string;
        tags: string;
        folderId: string | null;
        isPinned: number;
    }>;
    senderDeviceId: string;
    senderDeviceName: string;
}

export interface SyncResponse {
    accepted: number;
    rejected: number;
    merged: number;
    serverPayload: SyncPayload;
}
```

注意：

- 笔记已迁至独立的 `Note_Content` 表，**本次不参与同步**。`read_local_payload` 的 `notes` 始终为空数组，`merge_payload` 跳过 `type = "note"` 的文档并忽略收到的 `notes`；
- `NotePayload` 结构与 `notes` 字段仅为新旧客户端互连时兼容保留；
- 同步中的 `notes.isPinned` 是数字 0/1，而普通 API 的 `Note.isPinned` 是布尔值。

### 合并计数

| 字段 | 含义 |
|---|---|
| `accepted` | 本地不存在、直接插入的文档数 |
| `merged` | 对方 `updated_at` 更新、覆盖本地的文档数 |
| `rejected` | 时间相等或本地更新的文档数 |

## 6.10 前端事件

| 事件 | 载体 | 载荷 | 触发方 / 监听方 |
|---|---|---|---|
| `mysystem:sync-completed` | `window` CustomEvent | 无 | `useSyncSettings` 触发；书架、笔记列表监听刷新 |
| `mysystem:annotation-added` | `window` CustomEvent | `Annotation` | `EpubReader` 触发；`AnnotationPanel` 刷新 |

`EventBus`（`ModuleContext.events`）提供 `on` / `off` / `emit`，当前业务代码主要使用上面的 window 事件。

## 6.11 前后端类型对照速查

| 概念 | Rust | TypeScript |
|---|---|---|
| 笔记 | `Note` | `Note` |
| 新建笔记 | `CreateNoteInput` + `device_id` | `CreateNoteInput`（无 deviceId） |
| 更新笔记 | `UpdateNoteInput` + `device_id` | `UpdateNoteInput` |
| 文件夹 | `Folder` | `Folder` / `FolderNode` |
| 书籍 | `Book` | `Book` |
| 标注 | `Annotation` | `Annotation` |
| 基础文档 | `BaseDocument` | `BaseDocument` |
| 同步包 | `SyncPayload` | `SyncPayload` |
| 同步结果 | `SyncResponse` | `SyncResponse` |
| 设备 | `DeviceInfo` | `DeviceInfo` |
| 日志文件 | `LogFileInfo` | 前端 `LogFileInfo`（logger.ts） |

新增字段时，必须同时修改 Rust 结构体、数据库列（如需要）、前端类型与 `api.ts` 封装，否则序列化会丢字段或类型检查失败。
