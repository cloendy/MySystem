# 08 开发指南

## 8.1 环境准备

| 依赖 | 说明 |
|---|---|
| Node.js 20+ | 前端构建 |
| pnpm | 包管理器；仓库只有 `pnpm-lock.yaml` |
| Rust stable | Tauri 后端 |
| Tauri 系统依赖 | Windows 需要 WebView2、MSVC 构建工具 |
| VS Code | 推荐扩展见 `.vscode/extensions.json`：Vue - Official、Tauri、rust-analyzer |

安装依赖：

```bash
pnpm install
```

## 8.2 常用命令

```bash
pnpm dev            # 仅 Vite，端口 1420（strictPort）
pnpm tauri dev      # 完整开发（先启动 Vite，再编译并运行 Tauri）
pnpm build          # vue-tsc --noEmit + vite build
pnpm tauri build    # 打包（内部先执行 pnpm build）
cd src-tauri && cargo check
```

说明：

- `pnpm dev` 只适合调样式/静态页面，Tauri `invoke` 不可用。
- 新增/删除 `src/modules/*` 目录后必须重启 `pnpm dev`，因为 `import.meta.glob` 在启动时展开。
- 未配置 lint 与自动化测试；`vue-tsc --noEmit` 是前端唯一静态检查。
- Rust 侧用 `cargo check` 快速检查；完整构建用 `pnpm tauri dev` 或 `pnpm tauri build`。
- 如果从 WSL 调用 Windows 工具链，需要使用 Windows 的 `cargo.exe` 并保持 `CARGO_HOME`/`RUSTUP_HOME` 为 Windows 环境；具体路径因机器而异。

## 8.3 新增功能模块

以 `demo` 模块为例。

### 1. 前端模块目录

```
src/modules/demo/
├── index.ts          # 必须：默认导出 ModuleInterface
├── api.ts            # invoke 封装
├── types.ts          # 前端类型
├── stores/demo.ts    # Pinia store（可选）
├── views/DemoView.vue
└── components/       # 可选
```

### 2. 模块入口

```ts
import { logger } from '../../platform/services/logger';
import type { ModuleInterface } from '../../platform/services/module-types';

const demoModule: ModuleInterface = {
    id: 'demo',
    name: '示例',
    version: '1.0.0',
    icon: '🧪',
    order: 30,
    enabled: { windows: true, android: true },

    async onLoad(context) {
        logger.info('[Demo] 模块已加载，平台:', context.platform);
    },

    getRoutes() {
        return [
            {
                path: '/',
                name: 'demo-list',
                component: () => import('./views/DemoView.vue'),
            },
        ];
    },
};

export default demoModule;
```

### 3. 生效

- 重启 `pnpm dev`；
- 路由自动注册为 `/demo/`，名称为 `demo:demo-list`；
- 导航按 `order` 自动出现；
- 启动页会跳到 `order` 最小的模块。

### 4. 后端（如需持久化）

1. 在 `src-tauri/src/platform/database_init.rs` 添加建表语句；
2. 在 `src-tauri/src/modules/demo/mod.rs` 实现 `#[tauri::command]`；
3. 在 `src-tauri/src/modules/mod.rs` 声明 `pub mod demo;`；
4. 在 `src-tauri/src/commands.rs` 的 `invoke_handler()` 追加命令；
5. 前端 `api.ts` 封装 invoke。

模块 Rust 侧只依赖 `platform/`，不要反向让平台依赖业务模块。

## 8.4 新增数据表

1. 在 `database_init.rs` 的 `execute_batch` 中添加 `CREATE TABLE IF NOT EXISTS`；
2. 如果需要索引，一并添加 `CREATE INDEX IF NOT EXISTS`；
3. 如果依赖 `documents`，使用 `document_id TEXT PRIMARY KEY REFERENCES documents(id)`；
4. 在模块 Rust 实现中读写；
5. 更新 [05-数据库设计.md](05-数据库设计.md)。
6. 若涉及同步，还要扩展 `sync_payload.rs` 的 payload 与合并逻辑。

注意：当前没有迁移版本号机制，`CREATE TABLE IF NOT EXISTS` 不会给已有表加列。修改已有表结构时，需要在启动初始化中写显式的兼容/迁移逻辑（参考 `migrate_legacy_folders`）。


```rust
// commands.rs
tauri::generate_handler![
```

## 8.6 日志规范

### Rust

```rust
crate::log_info!("[Notepad] 新建笔记: {}", title);
crate::log_warn!("[Data] 数据目录不可写: {}", dir.display());
crate::log_error!("[Sync] 合并失败: {}", e);
crate::log_debug!("...");
```

- 禁止 `println!` / `eprintln!` / `dbg!`。
- 前缀使用模块名：`[Notepad]`、`[Reader]`、`[Sync]`、`[HTTP]`、`[Discovery]`、`[Import]`、`[Data]`。

### 前端

```ts
import { logger } from '../../../platform/services/logger';
logger.info('[Notepad] 打开笔记: ...');
```

- 禁止裸 `console.*`（调试时临时使用后应删除）。
- 业务日志放在 store 或视图的关键结果处，不要逐字符、逐页写。
- 高频日志节流：搜索 1s、自动保存 5s、翻页保存由防抖控制。
- UI 点击日志由 `ui-logging.ts` 自动记录，无需手写。

## 8.7 确认弹窗

删除等危险操作必须使用：

```ts
import { confirmAction } from '../../../platform/services/dialog';

if (!(await confirmAction('确定删除？', '删除'))) return;
```

不要使用 `window.confirm`：Tauri WebView 中点击取消可能仍返回 `true`，会导致误删除。

## 8.8 文件夹相关约束（修改前必读）

- 表名是 `Note_Folders`，不是 `folders`；
- 默认文件夹固定 `0001`，不可改名/删除，不可添加子文件夹；
- 层级由后端计算：根级 1，最大 3；删除时子级上移，后代层级递归调整；
- 同级唯一性由唯一索引 + 业务校验共同保证；
- 删除后前端必须 `fetchFolders()`，不能只改本地数组（否则孤儿节点会被树当作根节点）；
- 重命名是内联输入框，不弹窗；空名/同名视为取消；
- 子文件夹冗余 `Folder_Parent_Name`，父级重命名或子级移动时要同步更新。

## 8.9 UI 与样式

- 通用控件优先使用 `src/styles/common.css`：`.btn`、`.btn-primary`、`.btn-danger`、`.toolbar`、`.empty-state`、`.overlay`、`.side-panel`、`.text-input`、`.tag-chip`、`.switch`。
- 组件私有样式使用 `<style scoped>`。
- 主色 `#2c3e50`，危险色 `#c0392b`，成功色 `#27ae60`。
- 新增页面保持中文文案、13–14px 正文、4px 圆角、0.15s 过渡。
- Android 端注意安全区：顶部 `env(safe-area-inset-top)`，底部 `env(safe-area-inset-bottom)`。
- 桌面/移动差异通过 `detectPlatform()` 判断，不要在组件里直接读 userAgent。

## 8.10 同步相关修改

- 同步 payload 定义在 `platform/sync_payload.rs`，前端类型在 `platform/services/config.ts`；
- 合并规则只比较 `updated_at`，相等视为无变化；
- 新增同步字段时要同时修改：
  1. `read_local_payload` 的 SELECT；
  2. `merge_payload` 的 INSERT/UPDATE；
  3. Rust 结构体与前端类型；
  4. HTTP 文档。
- 当前不同步 `Note_Folders`、`books`、`annotations`，扩展时注意外键/指向关系。

## 8.11 验证流程

提交前至少执行：

```bash
pnpm build
cd src-tauri && cargo check
```

手工验证建议：

1. 启动应用，确认模块、路由正常；
2. 记事本：新建/编辑/自动保存/搜索/标签/文件夹增删改移；
3. 阅读器：导入、打开、翻页、进度恢复、标注；
4. 设置：同步开关、扫描、连接、同步、日志查看；
5. 查看 `data/log/mysystem-*.log` 是否有异常错误。

## 8.12 调试技巧

- **看日志**：设置页「查看日志」，或直接打开 `<data>/log/mysystem-YYYY-MM-DD.log`。
- **看数据库**：先关闭应用，复制 `mydata.db`（以及可能存在的 `-wal`、`-shm`）到临时目录，再用 `sqlite3` 打开，避免锁冲突。
- **前端报 command not found**：检查命令是否在 `commands.rs` 注册、参数名是否匹配。
- **模块不出现**：重启 Vite；检查 `index.ts` 默认导出与 `id`；查看 `[ModuleLoader]` 日志。
- **资源加载失败**：检查 CSP、asset 协议授权、文件是否位于 `<data>` 下。
- **不要提交 `data/`**：`.gitignore` 已忽略 `/data/`，数据库、书籍、日志不应进入版本库。

## 8.13 编码约定

- 注释、日志、UI 文案使用中文；标识符使用英文。
- 时间戳统一 Unix 毫秒。
- Rust 结构体统一 `#[serde(rename_all = "camelCase")]`。
- 模块通过自己的 `api.ts` 调 Rust，不经过 `platform/services/storage.ts` 的业务封装。
- 不在前端直接执行 SQL；数据库由 Rust 负责。
- 修改 spec 相关决策时，同步更新 [11-已知偏差与路线图.md](11-已知偏差与路线图.md)。
