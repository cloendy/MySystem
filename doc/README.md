## 推荐阅读顺序

1. 新人入门：01 → 02 → 03；
2. 前端开发：04 → 07（前端封装部分）→ 08；
3. 后端/数据开发：05 → 06 → 07（命令部分）→ 08；
4. 发布与排错：09 → 10；
5. 做技术决策前：02 → 11（需要追溯原始设计意图时再看 `backup/` 中的旧设计文档）。

## 文档维护约定

- 新增或修改功能时，同步更新对应文档；涉及数据库或接口的改动至少更新 05/06/07。
- 更新文档使用 `update-docs` skill：仅在工作区无未提交更改时执行，先把当前文档备份到 `doc/backup/_YYYYMMDDNN/`（同日多次更新时序号递增），再修改文档。
- 文档中的路径、命令、字段名以仓库当前代码为准，避免只写概念不写落点。
- 代码注释、日志、UI 文案使用中文；标识符、命令名、字段名使用英文。
- 时间戳统一为 Unix 毫秒（`i64` / `number`）。
- 文档内的“实现”“当前”均指当前分支 `feature.202611.v001` 的代码状态。
