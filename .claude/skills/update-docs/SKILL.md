# 更新文档

## 前提检查（必须先做）

1. 执行 `git status --porcelain`。
2. **有输出就停止**：列出未提交的改动，提示用户先提交或 stash。不要创建备份、不要修改任何文档。
3. 只有工作区干净时才继续。

## 1. 创建备份

- 备份根目录：`doc/backup/`。
- 本次备份目录：`doc/backup/_YYYYMMDDNN/`，例如 `_2026102201`。
  - `YYYYMMDD` 取当天本地日期（`date +%Y%m%d`）。
  - 同日已存在 `_YYYYMMDD01` 时，序号递增为 `02`、`03`……保持两位。
- 把 `doc/` 根目录下当前所有 `.md` 复制进本次备份目录；`doc/backup/` 自身不参与备份。
- 备份是更新前的快照，不要修改原文件。

## 2. 归档旧设计文档

`doc/personal-system-design-v2.md` 已不再作为参考，文档内容以 `doc/01-*.md` ~ `doc/12-*.md` 和当前代码为准。

- 如果它还在 `doc/` 根目录：**移动**到本次备份目录（移动优先于复制，避免重复）。
- 如果它已不在 `doc/` 根目录：不要恢复，也不要新建同名文件。
- 修正所有指向它的链接和说明：改为备份目录中的路径，或删除过期引用；历史说明只保留在 `12-变更记录.md`。

## 3. 更新文档

以当前代码为准，逐份核对 `doc/01` ~ `doc/12`：

- 优先核对易过时内容：目录结构、命令、数据表、接口、模块清单、配置项。
- 同步更新 `doc/README.md` 的索引与推荐阅读顺序。
- 在 `doc/12-变更记录.md` 追加本次更新条目：日期 + 更新内容概述。
- 文档中的相对链接必须指向真实存在的文件。
- 用户只要求更新某几份文档时，仍要检查它们关联的索引、链接和引用。

权威顺序：**当前代码 > `doc/01`~`doc/12` > `CLAUDE.md`**。备份目录只用于追溯历史，不作为修改依据。

## 4. 验证

- `grep -rn "personal-system-design-v2" doc/ CLAUDE.md`：只允许出现在备份目录或变更记录的历史说明中。
- 抽查 Markdown 链接目标是否存在。
- 用 `git status --porcelain` 汇总改动，向用户列出：备份目录、更新的文档、发现并修正的偏差。

## 不要做

- git 有未提交更改时不要开始。
- 不要跳过备份直接改文档。
- 不要把备份文件散落在 `doc/` 根目录。
- 不要重新把 `personal-system-design-v2.md` 当作设计依据。
- 不要自动提交，除非用户明确要求。
